# 兼容性与验证

目标：运行 Docker 的 Linux NAS，AMD64 或 ARM64，内核和挂载配置支持 bind propagation。

| 范围 | 状态 |
|---|---|
| 旧版 DXP4800 Pro 私人安装 | 项目历史记录有合成文件主备校验结果；2026-10-08 在线页面确认仍为 V0.10 |
| 0.12.0-beta.1 单元/API 测试 | 以本次 CI 与发布附件为准 |
| AMD64/ARM64 容器构建及合成导入 | 以对应版本 Actions 成功结果为准 |
| 新版绿联各型号实卡热插拔 | 尚未完成型号矩阵验收 |
| Docker Desktop USB 透传 | 不支持作为 NAS 热插拔验收环境 |

实际 NAS 验收：服务先启动→插卡发现→主备 SHA256→再次导入跳过→拔卡重插→暂停继续与终止→重启保留设置→自动来源排除系统盘与镜像。源只读检查应在插卡之后重新运行。测试版不能承诺掉电恢复或所有型号适配。

USB 总线不等于外置读卡器。内置/外置来源依据硬件连接证据；不足时显示未知，可手动设置。编号标识接口，不是卡的唯一身份。

主备处于同一个 RAID 或存储池可能共享故障域。程序检查路径重合与绑定别名，不证明物理设备独立。

Docker 只读子挂载与热插拔传播取决于宿主内核，参见 [Docker 官方说明](https://docs.docker.com/engine/storage/bind-mounts/)。不能用特权容器绕过问题。
