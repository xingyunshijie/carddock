升级到 NAS V1.0 构建2

本次将安装说明调整为参考教程的结构，标准项目使用 AUTHENTICATION_ENABLED=true 与 AUTHENTICATION_PASSWORD 设置单用户登录密码，取消生成器密钥流程。

从构建1升级

  • 在旧程序关闭自动导入并等待任务结束，备份原项目配置和 state。
  • 上传、解压构建2到新程序目录。编辑原 Docker 项目：把程序只读挂载指向新版，保持原 state 目录映射到 /state。
  • 保持来源、目标存储区、端口、UID/GID和容器内路径；将 ACCESS_TOKEN 替换为 AUTHENTICATION_ENABLED: "true" 和 AUTHENTICATION_PASSWORD: "自己的12位以上密码"。
  • 重新部署原项目。打开软件，用新设置的密码登录；旧的访问密钥文件不会覆盖显式设置的密码。

构建2的新安装示例目录为 /volume1/docker/carddock-nas-1.0-b2。升级时沿用旧 state，不能将新的空 state 覆盖已有记录，不要并行启动两个实例写同一状态目录。

旧 V0.10 / V0.11 实例

先保存旧配置、程序和状态备份，保留所有旧容器内路径。例如旧目标使用 /volume2/Media，新项目仍需映射该路径并加入 TARGET_ROOTS，不可直接换为 area1 再运行旧任务。

旧配置与历史继续保留；中断任务不会自动重跑。新规则不会自动移动旧归档，启用新的分类或模板时先在新目录测试。

没有设置新的 AUTHENTICATION 参数时，程序仍保留旧版访问密钥兼容；标准新安装使用密码认证。密码改动通过原 Docker 项目重新部署生效，已有登录会失效。

回退

关闭自动导入并等待任务结束，停止新版，恢复原项目配置、程序和升级前的 state 备份，再启动旧版。回退不会撤销已经拷贝的素材，不删除或格式化源卡。
