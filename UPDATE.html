影像归仓 NAS 更新与迁移

构建3：改用完整程序镜像

不再上传和挂载程序目录，不再在启动时安装 Python 依赖。不需要 carddock-admin；使用 Docker 配置中的自设密码登录。

尚未正式使用的新安装

按 NAS安装说明.md 新建 carddock 项目即可。旧解压文件夹不参与新程序运行，确认没有素材和历史后自行保留或移走。

已有配置和历史

先关闭自动导入并等所有传输结束，备份旧 state 目录及项目配置，再停止旧容器。不得让两个容器同时写同一个状态目录。

用新配置替换原项目配置，保留项目名、原有共享目录映射和容器内路径。如果要继续使用旧历史，将 carddock-data:/state 那一行改成 旧state绝对路径:/state，并删除配置末尾不再使用的 volumes: carddock-data: 定义。旧 state 仍需可供容器 UID/GID 写入。

不要把旧 state 复制进程序目录映射，也不要改主盘内的素材。若旧目录不是 /storage/area1 和 /storage/area2，应保留原容器内路径，并在 environment 中设置原来的 SOURCE_ROOTS、MANUAL_SOURCE_ROOTS 和 TARGET_ROOTS。

今后更新和回退

保存当前项目配置与 state 备份。将 image 修改为要安装的固定版本，重新部署原项目。保留数据卷；不勾选“同时删除数据卷”。

回退时恢复原镜像或旧项目配置，并在必要时恢复升级前 state 备份。构建2使用上传目录启动，回退构建2需保留原程序目录；仅把新 image 标签改成构建2不能代替旧配置。

删除

删除项目和镜像会停止程序。配置与历史在专用数据卷中；只有确定不再需要时才删除该数据卷。照片、RAW、视频、归档及备份目录始终独立保存。
