NAS 1.5.2 更新与迁移

NAS 更新提醒与一键更新

推荐安装配置使用 ghcr.io/xingyunshijie/carddock:latest，跟随已测试并发布的新版镜像。固定版本配置另见 compose.version.yaml，供需要锁定版本或回退的用户使用；固定旧版本不会自动跟随其他版本号。

绿联 NAS 支持镜像更新检查的版本，可在 Docker 管理中开启检查；当该标签的镜像发生变化，项目列表会按 NAS 自身检查周期提示更新。结束拷贝并关闭自动导入后，使用该项目的更新入口；系统会拉取新镜像、重建容器。更新期间服务短暂中断。

保留同一个项目名、密码、端口以及 data/archive/inbox 映射，设置、历史与素材继续保留。不要删除项目文件夹。不要在任务运行时更新；NAS 的更新按钮不能自动等待影像归仓传输完成。

已有固定版本安装：仅将原配置 image 改为上面的 latest，保留其他设置并重新部署一次。之后无需每次修改版本号。其他品牌 NAS 的检测周期和按钮名称不同；没有检查功能时，手动拉取 latest 并重新部署原项目。

官方功能说明：https://support.ugnas.com/detail/article/zh-CN/289

新安装

按 NAS安装说明.md 创建项目。默认使用项目内 inbox、archive、data，不依赖特定 NAS 的共享目录名称。新安装自动创建 archive/影像归仓 作为主盘，备份留空。

已有实例

关闭自动导入，等待任务结束，备份原项目配置和 state/data 后再更新。保持项目名、原状态映射、共享目录映射和容器内路径。不要把新的空 data 替换掉已有 state，不要让两个容器同时写一个状态目录。

若从构建3升级且原目标为 /storage/area1 与 /storage/area2，必须保留原映射，并在 environment 中显式设置：

      TARGET_ROOTS: /storage/area1:/storage/area2
      MANUAL_SOURCE_ROOTS: /manual/area1:/manual/area2

保持原来的运行身份：构建3默认1000:10，可添加 PUID: "1000"、PGID: "10"，也可保留原 user 配置。实际身份以原项目为准。已有设置不被新默认目录覆盖。

更新、回退和删除

更新只修改镜像版本，保留所有目录和数据卷。回退时恢复原项目配置及必要的升级前状态备份；构建2还需要原上传程序目录。

删除项目文件夹会同时删除其中 inbox、archive 的素材和 data 的历史，不能当成普通程序卸载目录直接清理。旧版使用 Docker 数据卷时也应保留原卷，直到确认资料已迁移。
