影像归仓 · 安装与使用帮助

星云视界 出品 ｜版本 0.12.0-beta.1 ｜2026-10-08

这是公开测试版。先使用可重新获取的测试素材验证，确认结果后再导入正式拍摄内容。请从 github.com/xingyunshijie/carddock 的 Releases 下载官方版本。

一、它能做什么

把摄影存储卡复制到 NAS 主文件夹，完成校验后，再从主文件夹复制到一个可选备份文件夹。支持自动或手动开始、照片/视频/声音分类、重复文件复核、暂停继续、终止和校验报告。

不会删除或格式化原卡，不会修改媒体、转码或生成代理。应用不是绿联官方软件。

二、安装前准备

- NAS 需运行 Linux 并安装 Docker；镜像分别提供 AMD64（x86_64）与 ARM64（aarch64）。在 NAS 系统信息中核对架构。

- 准备主导入文件夹、可选备份文件夹、独立状态文件夹。给运行账户主备和状态目录的读写权限、源卡目录读取权限。

- 状态文件夹用于保存配置、密钥和任务记录，不能放在源卡或主备目录中，也不要在更新时清空。

- 核对账户 UID/GID。它们是数字身份，不是用户名；示例 1000 不代表每台 NAS 都相同。管理员终端可运行 id 用户名。

- 核对外接卡自动挂载父目录。部分绿联为 /mnt/@usb，请以实际系统为准；不要填只属于当前一张卡的 sde1 等子目录。

- 主备建议使用不同存储设备。两个文件夹、两个共享名，甚至同一个 RAID 内两个目录，都不等于两块独立备份盘。

三、绿联 Docker 图形界面安装

1. 下载 carddock-版本-install.zip，解压后，用电脑浏览器打开 setup.html。此配置页面离线工作，不上传填写内容。

2. 填入源挂载父目录、主文件夹、可选备份文件夹、独立状态目录及 UID/GID。目录要先创建，不能只在表单里填一个不存在的路径。

3. 若想从网页浏览更多 NAS 存储区，在“其他允许浏览的目标存储区”中每行填写一个共享目录。应用只能访问配置中授权的目录。不要映射整个系统根目录。

4. 保存安装助手生成的随机密钥，点击“下载 compose.yaml”。此文件包含密钥，不要传到公开论坛或 GitHub。

5. 在绿联 Docker 应用进入“项目”，创建项目并导入 compose.yaml，启动部署。不同 UGOS 版本的按钮名称可能略有区别。

6. 浏览器打开 http://NAS局域网IP:18080；改过端口就使用自己的端口。输入安装时生成的密钥。

7. Docker 容器终端运行 python /app/preflight.py，检查账户权限、源只读与设备信息。插卡后重新检查，不能仅检查空的源父目录。

示例路径只是说明：主目录 /volume1/Media/Imports，备份 /volume2/MediaBackup/Imports，状态 /volume1/docker/carddock-state。请全部替换为自己的实际路径。

四、镜像无法下载或离线安装

从同一 Release 下载对应 CPU 的 carddock-版本-amd64.tar.gz 或 carddock-版本-arm64.tar.gz。解压为 tar 后，在 Docker 镜像管理中导入。

安装助手“镜像”改为 carddock:版本-amd64 或 carddock:版本-arm64，与导入镜像标签完全一致，再生成 Compose。不要把 ARM64 镜像给 AMD64 机器使用。

下载页提供 SHA256SUMS；可用系统 SHA256 工具核对安装包和镜像未损坏。Windows PowerShell 使用 Get-FileHash 文件名 -Algorithm SHA256；macOS 使用 shasum -a 256 文件名；Linux 使用 sha256sum 文件名。

五、第一次手动导入

1. 把测试存储卡插入 NAS。先确认 NAS 文件管理器能看到卡，再打开影像归仓并刷新数据源。

2. 左侧选卡；未识别品牌时可手动指定品牌、型号，或添加已映射的手动数据源。

3. 中间查看文件数量、容量和分类。预览最多显示 200 条，导入会处理所选范围内全部符合条件的文件。

4. 目标区点击“选择”，先选存储区，逐层进入文件夹，再点“使用当前目录”。支持“上一级”和“所有存储区”。网页显示容器内路径，存储区标签会注明对应 NAS 路径。

5. 主文件夹必选；备份可留空，也可选择一个。源、主、备份不能相同或互相包含。选好后保存设置。

6. 校验保持默认 SHA256，运行方式保持“手动”，点击“开始拷贝”。先核对少量素材的主备结果和导出报告。

六、开启自动插卡导入

选择“自动”并保存，或使用顶部开启自动导入按钮。后台运行，不必一直打开网页。当前已插入且符合识别条件的卡也可能开始导入；开启前先确认目标路径。

设置跨容器和 NAS 重启保留。NAS 必须负责自动挂载读卡器，Docker 必须正常启动。多张卡按顺序导入；未知设备需手动确认，不会因为是 USB 盘就自动复制。

自动识别依据常见品牌目录或媒体元数据，不保证覆盖每台相机。支持 Sony、Canon、Nikon、Panasonic、ARRI、DJI 的常见目录规则；型号也可以手动填。

七、分类、目录结构与重复文件

- RAW：ARW、CR2/CR3、NEF/NRW、RW2、DNG 等。

- JPG：JPG、JPEG；其他图片单独分类。

- 视频：MP4、MOV、MXF、MTS 等；声音包括 WAV、MP3、AAC 等。

- 视频代理：LRV，或符合 Proxy、SUB 等目录及约定命名规则的视频。不按分辨率猜测，也不生成代理。

“仅媒体”只复制识别到的媒体类型；需要 XML 等普通伴随文件时请关闭。“保留媒体父目录”适合按文件夹组织的相机素材。程序始终跳过隐藏文件、回收站、符号链接和特殊文件。

再次导入会检查目标文件内容，完整相同文件跳过；同名不同内容生成带内容摘要后缀的文件，保留原文件。中断后重新提交会复核完整文件；未完成的大文件从头复制，不支持半文件断点续传。

八、如何看懂校验与拔卡提示

SHA256 为默认内容校验；MD5 也校验内容。快速模式只核对数量与体积，无法发现大小相同的内容损坏。即使快速模式，已有同名文件也会用哈希判定是否重复。

“主文件夹校验完成，可拔卡”表示当前选中范围的文件已有主副本，后续备份读主副本，不再依赖原卡。它不表示备份也已完成，更不表示 NAS 已安全卸载。请到 NAS 界面执行安全弹出。

只有已配置的所有目标均校验通过，才会显示全部完成。没有配置备份时会明确显示未设置备份。所有需要的副本完成并检查之前，不要格式化原卡。

九、暂停、继续、终止与速度

“暂停”会保留任务，可能仍有文件句柄打开；不要把暂停当成可以拔卡。“继续”从当前进度恢复。

“终止”会停止自动导入，并等待任务关闭文件、清理当前临时文件；等界面显示“已终止”及文件释放提示，再在 NAS 安全弹出。已完成文件保留，未完成部分不算完整备份。

速度为粗略平均写入速度，包含校验耗时，不含暂停时间，因此通常低于读卡器宣传峰值。文件大小、USB 链路、NAS 硬盘和校验模式都会影响速度。

十、读卡器来源与编号

设备可显示 NAS 内置读卡器或 USB 外置读卡器，并按接口保存 SD-01、SD-02 等编号。硬件证据不足时显示“位置待确认”，可以手动设置来源。

USB 总线不等于一定外置，部分内置读卡器也走 USB。SD 编号标记读卡器接口，不是存储卡唯一编号；换接口可能产生新编号。更改显示名不会改已有导入文件夹。

十一、密钥与访问

新安装生成独立随机密钥，保存在自己下载的 Compose 配置或 deployment/compose.json 中。使用局域网访问，不要直接映射公网端口。浏览器在当前标签会话中保存密钥。

忘记密钥可先查看自己的部署配置；已轮换过的密钥应由 NAS 管理员重置。终端管理员可运行 sudo python3 access-key.py reset --compose-file deployment/compose.json；GUI 项目需换成实际 Compose 文件路径。

“密钥管理”的 NAS 管理员网页认证需要额外安装 PAM/systemd 认证扩展与 HTTPS，不是普通 Docker 部署自动具备的功能。未安装扩展时使用终端重置说明，不要在其他网页输入 NAS 管理员密码。

十二、升级与回退

切换手动模式并保存，等任务结束。备份原 Compose 和状态目录，下载新版，只修改镜像版本并重新部署。保留原随机密钥、目录映射、账户及状态目录，不要重新生成一套配置覆盖旧安装。

失败时换回旧镜像标签或重新导入旧版镜像。旧版 Release 会保留。回退镜像不回退已经复制的素材，也不能自动回退跨版本的数据库格式；有格式迁移时须阅读对应更新说明。

不要在拷贝期间启用无条件自动更新容器。

十三、常见问题

项目显示 0/0：容器可能尚未创建。查看部署日志，核对镜像拉取、Compose 格式、真实目录是否存在。

容器无法启动：检查日志中的 Permission denied、路径不存在、端口占用、密钥未初始化或架构不匹配；不要用 privileged 或全盘 chmod 777 掩盖问题。

NAS 看到卡，程序看不到：检查 SOURCE_ROOTS 对应挂载父目录、rslave 传播、源读取权限、/sys 和宿主挂载表映射。部分内核的子挂载只读或传播不符合要求，需管理员处理后再测试。

只能选择两个目录：目前只映射了主备区域。增加明确允许的额外共享目录并重新部署后，选择器才能看到；单纯输入 NAS 路径不能越过 Docker 映射。

提示目录不可写：在 NAS 给运行 UID/GID 授予该目标的读写与进入权限。网络共享和外置文件系统的权限处理可能不同。

备份失败但主副本成功：保留原卡及已有文件，处理空间或连接问题后重新导入，会复核并补齐。已拔卡时需将主副本只读映射为手动来源补备份；当前没有独立的仅重试备份按钮。
